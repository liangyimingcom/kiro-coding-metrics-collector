[关键过程：第一次失败 → 排查 → 修复 → 第二次成功]

现象：Kiro 写了代码也 commit 了，但 dashboard 没更新。

排查（全部经 SSM 远程在两台机器上完成）：
  1) 服务端 ingest 日志：只有本机的 userSync 上报，无任何 stats 上报
       [ingest] userSync: user=Unknown ip=10.162.255.159 hostname=EC2AMAZ-INC6DOR
     => 插件活着、网络通，但 commit 统计从未发出
  2) 定位仓库：C:\workspace\calculator（Kiro 工作区）
  3) 检查仓库 .git/hooks/post-commit：★缺失★  <-- 根本原因
     => 第一次 commit (fd25b0a) 时钩子未装，commit 不触发统计

根因：插件在“激活时”给已打开的 git 仓库装 post-commit 钩子。
      若先启动插件、后 git init / 后打开项目，则钩子未被安装。

修复：在 Kiro 中执行 “Developer: Reload Window”（或重启 Kiro），
      插件重新扫描并补装 post-commit 钩子；随后再 commit 一次。

[指标解读 / 两次提交最终效果]

* 最终效果 = 只统计了第二次 commit。第一次（钩子未装）永久丢失，
  不会自动补报，也不会与第二次累加。机制本质：只统计“启用监控后”的 commit。

* ai_additions(20) = 最终留在 commit 里、归因为 AI 的净行数
* total_ai_additions(60) = AI 整个编码过程的累计写入动作（含被改写/删除的过程量）
  -> 二者不等是预期：区分“过程努力”与“最终归因”
* AI 占比 = (ai - mixed*0.5)/(ai + human - mixed) = 1.0（100% AI）
* 数据库 / 聚合 API / tool_model 三处一致，指标自洽准确。
